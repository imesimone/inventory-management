Factory Inventory Management System

A demo full-stack application: a Vue 3 single-page app talks to a FastAPI service that serves in-memory data loaded from JSON files. There is no database.

Tech stack

Two processes run locally. The browser loads the frontend from Vite and calls the API directly across origins.

Frontend

:3000
  • Vue 3 Options-style setup()
  • Vue Router 4 6 routes
  • Axios HTTP client
  • Vite 8 dev server and build
  • Custom SVG charts no chart library

Backend

:8001
  • FastAPI served by Uvicorn
  • Pydantic v2 response models
  • Python 3.11+ managed with uv
  • CORS all origins allowed

Data

JSON files
  • server/data/*.json
  • Loaded once at import by mock_data.py
  • Held in module-level lists
  • Changes are not persisted

Tooling

pytest
  • FastAPI TestClient
  • Tests in tests/backend/
  • Playwright and GitHub MCP servers via .mcp.json

System architecture

The frontend holds all view state and derived calculations. The backend filters and validates data. The data layer is read from disk once at startup.

Data flow

Filters are global. Changing one in the filter bar reloads every view that depends on it.

Filter changes

The user picks a period, warehouse, category or status in the filter bar. The values are shared refs in useFilters.

View reacts

The active view watches the filters and calls getCurrentFilters() to get a plain object, with the period renamed to month.

Request is built

api.js turns the object into a query string and skips any value equal to all. Dashboard loads four calls in parallel.

Server filters

The handler runs apply_filters, then filter_by_month for orders. The result is checked against the Pydantic response model.

View derives

Raw responses go into refs. Totals, chart series and tables are computed properties, so they update on their own.

views/*.vue

Example: Q2 orders from one warehouse

selectedPeriod = "Q2-2025"   selectedLocation = "San Francisco"
  -> { warehouse: "San Francisco", category: "all", status: "all", month: "Q2-2025" }
  -> GET /api/orders?warehouse=San%20Francisco&month=Q2-2025
  -> month "Q2-2025" expands to 2025-04, 2025-05, 2025-06 and matches order_date

Frontend structure

Where state lives

  • Filters: module-level refs in useFilters, shared as a singleton by every component.
  • Language and currency: useI18n stores the locale in localStorage. English maps to USD, Japanese to JPY.
  • User and tasks: useAuth holds a hardcoded mock user.
  • Server data: local refs in each view, with computed properties on top.

Conventions

  • Views are one file per route in client/src/views/. Detail modals live in components/.
  • Styling is scoped CSS in each file, with global rules in App.vue.
  • Palette is slate and gray, with green, blue, yellow and red for status.
  • The API base URL is hardcoded to http://localhost:8001 in api.js.

Known gaps

Found while reading the code

  • api.js calls /api/tasks (get, create, delete, toggle) and /api/purchase-orders (create, get), but main.py defines no such routes. Those calls will return 404 until the backend adds them. A CreatePurchaseOrderRequest model already exists for the purchase order route.
  • Backlog.vue exists but is not registered in the router. Backlog data is shown on the Dashboard through BacklogDetailModal.
  • /api/backlog and the backlog count in /api/dashboard/summary ignore all filters.
  • /api/reports/quarterly repeats the quarter mapping by hand instead of reusing QUARTER_MAP.
